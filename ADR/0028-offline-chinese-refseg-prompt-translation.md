# ADR-0028: RefSeg 中文提示离线转译

## 状态

Accepted

## 背景

RefSeg checkpoint 使用 RRSIS-D 英文指代表达和 OpenCLIP `ViT-L-14/openai` 训练。Web 界面面向中文用户，直接把“最上方的飞机”等中文提示送入现有文本编码器时响应不稳定，可能产生空 Mask。此问题不能通过修改界面标签解决，也不能在未重新训练的情况下替换文本编码器。

## 决策

1. 在 `tasks/routing/adapters/refseg.py` 的 Web Adapter 边界增加确定性的离线中文转译，不修改 `RefSegPredictor`、OpenCLIP、模型结构或 checkpoint。
2. 转译范围限定为 RRSIS-D 常用目标类别，以及位置、颜色和大小描述；例如“最上方的飞机”转为 `the topmost airplane`。
3. 英文提示原样传递。无法识别目标类别或包含多个类别、复杂关系的中文提示显式返回输入错误，不静默丢弃语义。
4. 推理摘要同时记录原始提示、实际模型提示和是否发生转译；浏览器向用户展示实际英文提示。
5. 空 Mask 仍是合法模型输出，但界面必须显示“未找到符合描述的目标”，不能仅显示“任务执行完成”。

## 备选方案

- 替换为多语言文本编码器：暂不采用。会破坏现有 checkpoint 的文本特征分布，需要重新训练和完整评测。
- 接入在线翻译或大模型服务：暂不采用。会增加网络、凭据、延迟、隐私和部署依赖，不符合当前本地零新增依赖边界。
- 继续直接编码中文：拒绝。真实样例已证明空间关系响应不稳定，且界面无法解释模型实际接收的语义。
- 对所有中文做不受限的词典替换：拒绝。复杂关系容易被错误简化，显式拒绝比生成错误提示更安全。

## 影响

- 常见中文遥感目标描述可以在当前英文 checkpoint 上稳定使用，且无需重新训练。
- 支持范围是有限、可测试的，不等价于通用机器翻译；复杂关系仍建议直接使用英文。
- 新类别或新的中文表达需要显式扩展映射和测试。
- 测试必须覆盖重叠类别词、单目标限制、英文直通、转译摘要和真实 HTTP 推理。
